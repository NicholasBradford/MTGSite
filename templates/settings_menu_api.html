MTGSite Settings Menu Reference

This document describes the current app_settings.json system and the settings that should be exposed in the MTGSite settings menu.

1. Where the settings file lives

The settings manager looks for the settings file in this order:


1. MTGSITE_SETTINGS_PATH from .env
2. data/app_settings.json

2. Current full settings JSON

This is the current working settings structure based on the settings work done so far.


{
  "schema_version": 1,
  "features": {
    "planeswalker_collection": true,
    "trade_screen": true,
    "edh_decks": true
  },
  "homepage": {
    "color_scheme": "teal",
    "default_view_mode": "grid"
  },
  "autosorter": {
    "enabled": true,
    "strategy": "default"
  }
}

If a setting is missing, the app falls back to the default in services/app_settings.py.

3. Settings menu sections

The settings menu should be divided into these sections:


Feature Toggles
Homepage Appearance
Inventory Autosorter

Feature Toggles

These settings live under:


"features": { }

features.planeswalker_collection

Type: boolean

Default: true

Menu label: Enable Planeswalker Collection

What it controls:

• Shows or hides homepage/sidebar links to the Planeswalker collection.

• Should block Planeswalker routes when disabled.

• Does not delete planeswalker data.

JSON:


"planeswalker_collection": true

features.trade_screen

Type: boolean

Default: true

Menu label: Enable Trade Screen

What it controls:

• Shows or hides Trade Binder links and buttons.

• Should block trade routes when disabled.

• Does not delete existing trade records or tradeable flags.

JSON:


"trade_screen": true

features.edh_decks

Type: boolean

Default: true

Menu label: Enable EDH / Commander Decks

What it controls:

• Shows or hides EDH/deck management links.

• Should block EDH routes when disabled.

• Does not delete deck records or deck assignments.

JSON:


"edh_decks": true

Homepage Appearance

These settings live under:


"homepage": { }

Use site_setting("homepage", "setting_name", default) in templates.

homepage.color_scheme

Type: string

Default: teal

Menu label: Homepage Color Scheme

Current options:


teal
dark_green / green
blue
purple

JSON:


"color_scheme": "teal"

homepage.default_view_mode

Type: string

Default: grid

Menu label: Default Homepage View

Current options:


grid
table

JSON:


"default_view_mode": "grid"

Current behavior:

• grid keeps the homepage path cards in a card grid.

• table can collapse the path cards into a single-column list if CSS is added.

• This does not currently change inventory search results unless you wire that route separately.

Inventory Autosorter

These settings live under:


"autosorter": { }

Use site_setting("autosorter", "setting_name", default) in templates.

autosorter.enabled

Type: boolean

Default: true

Menu label: Enable Inventory Autosorter

What it controls:

• Shows or hides the autosorter card on the admin dashboard.

• Should also block the sorter route so users cannot run it manually by URL.

• Does not move cards back if turned off after sorting.

JSON:


"enabled": true

autosorter.strategy

Type: string

Default: default

Menu label: Autosorter Strategy

Current working option:


default
alphabetical
color_only
set

Current default behavior:


Basic lands -> Land (Basic)
Other lands -> Land (Util)
Nonlands -> color prefix + alphabetical range

Examples of default destination boxes:


W-A:G
W-H:R
W-S:Z
U-A:G
B-H:R
R-S:Z
G-A:G
M-H:R
C-A:M
C-N:Z
Land (Basic)
Land (Util)

JSON:


"strategy": "default"

Live reload behavior

The settings manager checks app_settings.json for changes before each request.

That means:


Edit app_settings.json
Save file
Refresh the website or make a new request
The new setting is used

If the JSON file is invalid, the app should keep the last valid settings and print an error to the server log.

• Use lowercase true and false for booleans.

• Put strings in double quotes.

• Do not add trailing commas.

• Save the file, then refresh the site.

• If a setting does not appear to change, check whether the relevant template or route has actually been wired to read it.

Valid:


"trade_screen": false

Invalid:


"trade_screen": False,
